# Admin Form UX Enhancement: Text → Dropdown Conversion

## Goal
Convert textual input fields across all admin CRUD pages to dropdowns/selects for better UX — preventing typos, standardizing data, and enabling auto-population (e.g. selecting a country auto-fills the flag emoji and localized names).

## Architecture Context
- All admin forms use `EntityFormDialog` with `SectionDef[]` / `FieldDef` objects
- Existing reusable components: `CountrySelect`, `CitySelect`, shadcn `Select`
- Existing data hooks: `useCountries()`, `useStates()`, `useCities()`, `useCountryByCode()`
- No new npm packages needed — `country-state-city`, `i18n-iso-countries`, and Radix Select are already installed
- Flag emojis generated from ISO codes via native Unicode regional indicator symbols

---

## Files to Create

### 1. `resources/js/data/adminSelectOptions.ts`
Central registry of all static dropdown option lists:
- **VISA_REGIONS** — Geographic/political groupings: Schengen Area, European Union, Gulf Cooperation Council (GCC), African Union, ASEAN, Americas, United Kingdom, Other
- **CABIN_CLASSES** — Economy, Premium Economy, Business, First
- **FLIGHT_STOPS** — Direct, 1 Stop, 2+ Stops
- **STAR_RATINGS** — 1 through 5 stars
- **RATING_OPTIONS** — 0.0 through 5.0 (step 0.5)
- **FUEL_TYPES** — Petrol, Diesel, Electric, Hybrid, LPG
- **TRANSMISSION_TYPES** — Automatic, Manual, Semi-Automatic
- **BEST_TIME_OPTIONS** — January through December, or seasons
- **LANGUAGES** — Common languages with localized names
- **CURRENCIES** — Common currencies with codes
- **AIRLINE_NAMES** — Major airlines list

- **AIRPORT_OPTIONS** — Major world airports with IATA code, city, and country. Each option: `{ value: string (IATA code), city: string, country: string }`. ~150-200 airports covering all major international hubs.

Each option is `{ value: string; label: { en: string; fr: string; ar: string } }`.

### 2. `resources/js/data/airports.ts`
Major world airports with IATA codes, city names, and country codes. Used by flight form `from`/`to` dropdowns. ~150-200 entries covering all major international hubs (Tunis-Carthage TUN, Paris CDG, Dubai DXB, Istanbul IST, etc.).

### 3. `resources/js/lib/flagEmoji.ts`
Utility function `countryCodeToFlag(code: string): string` — converts 2-letter ISO code to flag emoji using Unicode regional indicator symbols. No external dependencies.

## Design Decisions

1. **Localized options**: Each option has `{ en, fr, ar }` labels. A helper `getOptionLabel(option, lang)` returns the correct translation.
2. **Auto-population (Visa)**: When user selects a country in CountrySelect, the form auto-fills code, flag, and all 3 name fields. User can still override name fields manually.
3. **No new packages**: Flag emoji from Unicode, static data in TS files, existing Radix Select for dropdowns.
4. **Consistent styling**: All new selects use the same shadcn `Select` component for visual consistency.
5. **Localized fields like `fuel_en/fr/ar`**: Use a single `<Select>` that sets `fuel_en`, `fuel_fr`, `fuel_ar` simultaneously to the same value (since fuel type is not language-dependent).
