# Investigate: Search-mode dropdown items don't navigate when clicked

## Problem
The user reports that clicking a search-mode dropdown item from the header navbar "does nothing" — the page doesn't navigate. But manually visiting `/hotels?q=something` works correctly.

## Investigation Summary

The search logic on listing pages is correct:
- Hotels page reads `params.get('q')` and initializes `searchQuery` state
- `matchesSearchText` filters correctly
- Manual URL navigation works

The `buildItemHref` function correctly generates search URLs:
```tsx
// nav-config.ts line 246-248
if (item.mode === 'search') {
    const query = item.label[lang] ?? item.label.en ?? '';
    return `${page.href}?q=${encodeURIComponent(query)}`;
}
```

The `DesktopFlyoutItems` renders Link components correctly:
```tsx
<Link to={buildItemHref(entry.pageKey, item, lang as 'en' | 'fr' | 'ar')}>
```

## Most Likely Cause

The hover-based flyout uses a 150ms delay (`useHoverDelay(150)`) before closing. When the user moves from the nav trigger to the flyout items, there's a risk the flyout closes before the click registers. But this should work with the 150ms buffer.

**Alternative cause**: The user may not have any search-mode items configured in the admin, or the items aren't being saved/loaded correctly. Need to verify the data flow.

## Recommended Next Step

Since the code analysis shows the search flow should work, I need the user to:
1. Confirm they have search-mode items configured in admin → Site Settings → Navigation
2. Check browser console for JavaScript errors when clicking the dropdown item
3. Check if the URL changes at all when clicking (even briefly)

If the user confirms items are configured and there are no errors, the fix would be to add `onClick` handlers to dropdown items as a fallback for the hover-based flyout.
