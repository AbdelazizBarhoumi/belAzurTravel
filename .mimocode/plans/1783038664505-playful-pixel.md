# Fix: Pages return 404 when enabled in footer but not in header

## Root Cause

The server-side middleware `EnforceNavSettings` only checks **header** entries to decide if a page is accessible. The client-side `NavRouteGuard` correctly checks **both header AND footer**. This mismatch causes a 404 before the SPA even loads when a page is:

- Disabled/removed from header navigation
- But still present in footer columns

The client guard (NavRouteGuard.tsx:32-45) correctly allows access if a page is in either header OR footer. The server middleware (EnforceNavSettings.php:102-115) only checks header, so it returns HTTP 404 before React ever boots.

## Fix

### File 1: `app/Http/Middleware/EnforceNavSettings.php` (lines 102-115)

Add footer check to match client-side logic:

```php
// For guests and clients, check if page is enabled in header or footer
$headerEntries = $navSettings['header'] ?? [];
$footerColumns = $navSettings['footer'] ?? [];

$isInHeader = false;
foreach ($headerEntries as $entry) {
    if (($entry['pageKey'] ?? null) === $matchedKey && ($entry['enabled'] ?? false)) {
        $isInHeader = true;
        break;
    }
}

$isInFooter = false;
foreach ($footerColumns as $column) {
    if (in_array($matchedKey, $column['pageKeys'] ?? [], true)) {
        $isInFooter = true;
        break;
    }
}

if (! $isInHeader && ! $isInFooter) {
    abort(404, __('messages.page_not_available'));
}
```

### File 2: `app/Http/Middleware/CheckNavPageEnabled.php` (lines 66-78)

Same fix for consistency (currently unused on affected routes but should match):

```php
$headerEntries = $navSettings['header'] ?? [];
$footerColumns = $navSettings['footer'] ?? [];

$pageEnabled = false;
foreach ($headerEntries as $entry) {
    if ($entry['pageKey'] === $pageKey && ($entry['enabled'] ?? false)) {
        $pageEnabled = true;
        break;
    }
}

if (! $pageEnabled) {
    foreach ($footerColumns as $column) {
        if (in_array($pageKey, $column['pageKeys'] ?? [], true)) {
            $pageEnabled = true;
            break;
        }
    }
}

if (! $pageEnabled) {
    abort(404, __('messages.page_not_available'));
}
```

## Verification

1. In admin, disable a page (e.g., `purchase-policy`) in header settings but keep it in footer
2. Visit `/purchase-policy` as a guest — should load the page (currently returns 404)
3. Disable in both header AND footer — should return 404 or redirect to `/`
4. Admin users should always have access regardless
5. Clear the `site_settings_nav` cache after changes: `php artisan cache:forget site_settings_nav`
