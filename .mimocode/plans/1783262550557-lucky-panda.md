# Plan: Fix Loading Overlay Disappearing Before Components Render

## Problem
The `RouteLoader` component (`resources/js/components/layout/RouteLoader.tsx`) uses a **time-based approach** to hide the loading overlay:
- Waits for minimum delay (600ms first load, 450ms subsequent)
- Waits for `window.onload` event or fallback timeout (1200ms)
- Uses `requestAnimationFrame` for frame timing

This causes the overlay to disappear **before** React Query data fetching completes, leaving skeleton screens visible.

## Root Cause
The overlay timing is based on document load events, not on React Query's actual data fetching state. When navigating to a page, React Query starts fetching data **after** the route changes, but the overlay hides based on fixed timeouts.

## Solution
Modify `RouteLoader` to wait for React Query's global `isFetching` state to reach 0 (no pending queries) before hiding the overlay, while keeping the minimum delay to prevent flickering on fast loads.

## Implementation Steps

### 1. Update `RouteLoader.tsx`
**File**: `resources/js/components/layout/RouteLoader.tsx`

Changes:
- Import `queryClient` from `@/lib/queryClient`
- Import `useIsFetching` from `@tanstack/react-query`
- Add `isFetching` state tracking using `useIsFetching()` hook
- Modify the `finish` function to check `isFetching === 0` before hiding
- Use a polling interval or effect to wait for `isFetching` to reach 0

```typescript
// Add imports
import { queryClient } from '@/lib/queryClient';
import { useIsFetching } from '@tanstack/react-query';

// Inside component
const isFetching = useIsFetching(); // Returns number of fetching queries

// In finish function, wait for isFetching === 0
const waitForQueries = () => {
  if (isFetching === 0) {
    setLoading(false);
    setFirstLoad(false);
  } else {
    // Poll until queries complete (with max timeout safety)
    setTimeout(waitForQueries, 100);
  }
};
```

### 2. Add Safety Timeout
- Keep a maximum total timeout (e.g., 10-15 seconds) to prevent infinite loading if queries fail
- This ensures the UI doesn't get stuck if there's a network error

- Navigate between pages with slow data fetching
- Verify overlay stays visible until skeletons are replaced with actual content
- Verify fast loads still show brief overlay (minimum delay prevents flicker)
- Verify error states don't cause infinite loading
