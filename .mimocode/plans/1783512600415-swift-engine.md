# Fix: Landing Section `isPageEnabled` Double-Gate Bug

## Problem

When enabling a section in the admin "Landing Sections" panel, it still doesn't render on the landing page. The root cause is a **double-gate**: the orchestrator (`LandingSections.tsx:40`) correctly checks `config.enabled` from the landing sections settings, but **7 out of 10 individual section components also check `isPageEnabled()` against the nav settings** (`settings.content?.nav?.settings`). This means a section must be enabled in **both** the landing sections panel **and** the navigation settings to render — which is the wrong behavior.

The nav settings should only control which pages appear in the header/footer navigation menu, not whether a landing section is visible.

## Affected Sections (7 of 10)

| Section | File | Line | Check |
|---------|------|------|-------|
| Hotels | `resources/js/components/sections/landing/HotelsSection.tsx` | 21 | `isPageEnabled('hotels', ...)` |
| Destinations | `resources/js/components/sections/landing/DestinationsSection.tsx` | 20 | `isPageEnabled('destinations', ...)` |
| Cars | `resources/js/components/sections/landing/CarsSection.tsx` | 17, 19 | `isPageEnabled('cars', ...)` |
| Flights | `resources/js/components/sections/landing/FlightsSection.tsx` | 16, 18 | `isPageEnabled('flights', ...)` |
| Events | `resources/js/components/sections/landing/EventsSection.tsx` | 18 | `isPageEnabled('events', ...)` |
| Deals | `resources/js/components/sections/landing/DealsSection.tsx` | 18 | `isPageEnabled('deals', ...)` |
| Blog | `resources/js/components/sections/landing/BlogSection.tsx` | 17 | `isPageEnabled('blog', ...)` |

## Unaffected Sections (3 of 10) — No changes needed

- `ToursSection.tsx` — no `isPageEnabled` check
- `OrganizedSection.tsx` — no `isPageEnabled` check
- `LocationSection.tsx` — no `isPageEnabled` check

## Fix

Remove the `isPageEnabled()` guard from each of the 7 affected section components. The orchestrator already handles enabled/disabled via `config.enabled`.

### Per-file changes:

**1. `HotelsSection.tsx`** — Remove line 12 (import) and line 21 (guard):
```diff
- import { isPageEnabled } from '@/lib/pageVisibility';
```
```diff
- if (!isPageEnabled('hotels', settings.content?.nav?.settings)) return null;
```
Also remove `useSiteSettings` import and hook call since they become unused (only used for nav check).

**2. `DestinationsSection.tsx`** — Remove line 10 (import) and lines 19-20 (guard):
```diff
- import { isPageEnabled } from '@/lib/pageVisibility';
```
```diff
- const navSettings = settings.content?.nav?.settings;
- if (!isPageEnabled('destinations', navSettings)) return null;
```
Also remove `useSiteSettings` import and hook call since they become unused.

**3. `CarsSection.tsx`** — Remove line 10 (import), simplify lines 16-19:
```diff
- import { isPageEnabled } from '@/lib/pageVisibility';
```
```diff
- const { settings } = useSiteSettings();
- const carsEnabled = isPageEnabled('cars', settings.content?.nav?.settings);
- const { data: cars = [] } = useCars(carsEnabled);
- if (!carsEnabled) return null;
+ const { data: cars = [] } = useCars();
```
Also remove `useSiteSettings` import since it becomes unused. The `useCars()` hook defaults to `enabled = true`.

**4. `FlightsSection.tsx`** — Same pattern as Cars:

