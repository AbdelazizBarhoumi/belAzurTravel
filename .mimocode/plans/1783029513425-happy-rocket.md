# Multi-Category-Type System Enhancement

## Goal
Transform the single "Category" dropdown per entity into a flexible multi-category-type system. Hotels can have separate dropdowns for "Category" (Luxury/Budget), "Star Rating" (3/4/5), "Style" (Beach/City), etc. Each type has a customizable multilingual label. New types auto-appear as new dropdowns in the add/edit form.

## Part 2: Nav Dropdown Category Types + Public Filtering

### Goal
When configuring navigation dropdowns in site settings, add a new mode "Category Types" that lets admins select a category type from the new `category_types` table. The dropdown then shows that type's values. On public pages, users can filter by one or more category values from any type.

## 2A. Reorganize dropdown modes to 3 options

Simplify to exactly 3 modes in the site settings nav dropdown:

### Mode 1: Dynamic Categories (`categories`)
- Admin selects a **category type** from the new `category_types` table
- The navbar shows ALL values of that type as dropdown links
- Each value links to the page with `?category_{type_key}={value_key}` filter

### Mode 2: Filter (`filter`)
- Admin selects a **single category value** from ALL values across ALL types for that entity
- The navbar shows that single item as a link
- Links to page with `?category_{type_key}={value_key}` filter

- Stays as is - admin types a search keyword

## 2C. URL param format

Use URL search params like:
```
/hotels?category_star-rating=5-stars,4-stars&category_style=beach,city
```

Format: `category_{type_key}={value_key1},{value_key2}`

This allows:
- Multiple values per type (comma-separated) = OR within type
- Multiple types in same URL = AND across types

### Filter mode URL format
When a filter item links to a page, the URL is:
```
/hotels?category_{typeKey}={valueKey}
```

### Categories mode URL format
When a categories dropdown item expands into values, each value links to:
```
/hotels?category_{typeKey}={valueKey}
```

## Database Changes

### New table: `category_types`
Defines what category types exist per entity.

| Column | Type | Notes |
|--------|------|-------|
| id | bigint PK | |
| entity_type | string, indexed | 'hotels', 'tours', etc. |
| key | string, indexed | auto-slug from English label |
| label | JSON | `{en, fr, ar}` — the dropdown label |
| sort_order | smallint, default 0 | |
| timestamps | | |
| UNIQUE(entity_type, key) | | |

### New table: `category_type_values`
The actual category options within each type.

| Column | Type | Notes |
|--------|------|-------|
| id | bigint PK | |
| category_type_id | FK → category_types | cascade delete |
| key | string, indexed | auto-slug from English name |
| name | JSON | `{en, fr, ar}` |
| timestamps | | |
| UNIQUE(category_type_id, key) | | |

### New table: `entity_category_assignments`
Pivot linking entities to their selected category values.

| Column | Type | Notes |
|--------|------|-------|
| id | bigint PK | |
| entity_type | string, indexed | 'hotels', 'tours', etc. |
| entity_id | bigint, indexed | |
| category_type_id | FK → category_types | cascade delete |
| category_value_id | FK → category_type_values | cascade delete |
| UNIQUE(entity_type, entity_id, category_type_id) | | one value per type per entity |

### Data migration seeder
1. For each `entity_type` in existing `categories`, create a `CategoryType` with label "Category"/"Catégorie"/"فئة"
2. Migrate each existing category row → `CategoryValue` linked to that type
3. For each entity with a `category_key` → create `EntityCategoryAssignment`
