# Fix: Filter-mode dropdown items broken on hotels, tours, travels pages

## Bug
Filter-mode nav dropdown items generate URLs like `/hotels?category_region=beaches`. The hotels, tours, and travels pages parse URL params but never use them to initialize filter state — the `categoryTypeFilters` useState is hardcoded to `{}`.

## Working pattern (Destinations page)
```tsx
// Parse ?category_* params
const initialCategoryTypeFilters = useMemo(() => {
    const filters: Record<string, string[]> = {};
    for (const [key, val] of params.entries()) {
        if (key.startsWith('category_')) {
            const typeKey = key.slice('category_'.length);
            filters[typeKey] = val.split(',').filter(Boolean);
        }
    }
    return filters;
}, [params]);
// Pass to useState
const [categoryTypeFilters, setCategoryTypeFilters] =
    useState<Record<string, string[]>>(initialCategoryTypeFilters);
```

## Fixes

### 1. Travels page (`pages/travels/index.tsx`)
**Easiest fix** — the `useMemo` parsing block already exists (lines 38-47) but `useState` ignores it (line 62).

Change line 62 from:
```tsx
const [categoryTypeFilters, setCategoryTypeFilters] = useState<Record<string, string[]>>({});
```
to:
```tsx
const [categoryTypeFilters, setCategoryTypeFilters] =
    useState<Record<string, string[]>>(initialCategoryTypeFilters);
```
