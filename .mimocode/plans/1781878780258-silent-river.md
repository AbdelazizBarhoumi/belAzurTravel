# Fix: Category Deletion — Show Affected Items Confirmation

## Problem

When an admin deletes a category that has items assigned to it:

1. **Backend** (`AdminCategoryController::destroy` at line 92-116) returns 409 with count, but the **frontend never sees it** because `apiFetch` throws on non-2xx before the confirmation check is reached
2. Even if it worked, the message only shows a **count** — the user wants to see **which items** will be affected

## Table Structure Reference

| Table | Name column | category_key | category (denormalized) |
|-------|------------|--------------|------------------------|
| hotels | `name` (json) | ✓ | ✓ |

## Changes

### 1. Backend: Return affected item names in the 409 response

**File:** `app/Http/Controllers/Api/AdminCategoryController.php`

Add a new `getAffectedEntities()` method that returns `[{ name, slug }]` for items using the category:

```php
private function getAffectedEntities(string $type, string $key): array
{
    $table = $this->getTableName($type);
    if (!$table) {
        return [];
    }

    // Events/deals/blog_posts use 'title' column; others use 'name'
    $nameColumn = in_array($table, ['events', 'deals', 'blog_posts']) ? 'title' : 'name';

    return DB::table($table)
        ->where('category_key', $key)
        ->select('slug', $nameColumn)
        ->get()
        ->map(fn ($row) => [
            'name' => $this->extractLocalizedName($row->$nameColumn, 'en'),
            'slug' => $row->slug,
        ])
        ->toArray();
}
```

Update `destroy()` to include the affected items list:

```php
if ($request->query('force') !== 'true' && $count > 0) {
    $affected = $this->getAffectedEntities($type, $key);
    return response()->json([
        'message' => "This category is assigned to {$count} item(s). Deleting it will set their category to null.",
        'count' => $count,
        'affected_items' => $affected,
        'requires_confirmation' => true,
    ], 409);
}
```

### 2. Frontend: Catch 409 error and show confirmation with item list

**File:** `resources/js/components/admin/CategoryManager.tsx`

Fix `handleDelete` to catch the 409 error from `apiFetch` and extract the data:

```typescript
const [confirmDialog, setConfirmDialog] = useState<{
    open: boolean;
    message: string;
    affectedItems: { name: string; slug: string }[];
    onDelete: () => void;
}>({ open: false, message: '', affectedItems: [], onDelete: () => {} });

const handleDelete = async (id: number, force = false) => {
    try {
        const res = await deleteCategory(id, force);
        clearCachedCategories();
        queryClient.invalidateQueries({ queryKey: ['categories'] });
        toast.success('Category deleted');
        loadCategories();
    } catch (err: any) {
        if (err?.status === 409 && err?.data?.requires_confirmation) {
            setConfirmDialog({
                open: true,
                message: err.data.message,
                affectedItems: err.data.affected_items || [],
                onDelete: () => handleDelete(id, true),
            });
            return;
        }
        toast.error('Failed to delete category');
    }
};
```

Replace the native `confirm()` with a proper confirmation dialog that lists affected items. Use existing shadcn/ui AlertDialog or a simple Dialog component already imported:

