# Plan: Decouple Footer Pages from Header Enabled Status

## Problem
Pages can only appear in the footer if they're first enabled in the header. The admin UI blocks adding footer-only pages in two places, making it impossible to show a page only in the footer.

## Changes

### 1. `resources/js/pages/admin/site-settings/AdminSiteSettingsFooter.tsx` (line 188-191)
**Remove the header-enabled filter** from the "Add Page" dropdown. Currently it only shows pages where `navEntry?.enabled` is true. Change to show ALL `AVAILABLE_PAGES` that aren't already in a footer column.

**Before:**
```tsx
AVAILABLE_PAGES.filter((p) => {
    const navEntry = draft.header.find((h) => h.pageKey === p.key);
    if (!navEntry?.enabled) return false;
    return !draft.footer.some((c) => c.pageKeys.includes(p.key));
})
```

**After:**
```tsx
AVAILABLE_PAGES.filter((p) =>
    !draft.footer.some((c) => c.pageKeys.includes(p.key))
)
```

### 2. `resources/js/pages/admin/site-settings/AdminSiteSettingsNav.tsx` (lines 100-105)
**Remove the auto-removal of footer entries** when a header entry is disabled. Currently `setHeader` strips disabled pages from all footer columns. Change so footer columns are untouched when toggling header enabled state.

**Before:**
```tsx
let nextFooter = draft.footer;
if (patch.enabled === false) {
    const pageKey = draft.header[idx].pageKey;
    nextFooter = draft.footer.map((c) => ({ ...c, pageKeys: c.pageKeys.filter((k) => k !== pageKey) }));
}
```

**After:**
```tsx
const nextFooter = draft.footer;
```

### 3. `resources/js/components/nav/NavRouteGuard.tsx`
**No changes needed** — already checks both `isInHeader` and `isInFooter` for access control.
