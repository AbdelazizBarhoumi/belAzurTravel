# Complaints & Refund Management System
> Dispositif de gestion de réclamation et remboursement

## Overview

Extend the existing `SupportInquiry` system to support two distinct request types:
1. **Complaints (Réclamations)** — general complaints with categories
2. **Refund Requests (Demandes de remboursement)** — tied to specific bookings with refund amount tracking

---

## 1. Database Migration

**New file:** `database/migrations/2026_06_22_000001_add_complaint_refund_fields_to_support_inquiries_table.php`

Add columns to `support_inquiries`:
- `type` — string, enum: `complaint` | `refund_request` | `general` (default: `general` for backwards compat)
- `category` — nullable string, complaint category: `service_quality` | `booking_issue` | `payment_problem` | `cancellation` | `other`
- `booking_id` — nullable FK to `bookings` table (for refund requests)
- `refund_amount` — nullable integer (requested refund amount in TND cents)
- `refund_reason` — nullable JSON (localized refund justification)
- `refund_status` — nullable string, enum: `pending` | `approved` | `rejected` | `refunded`
- `admin_response` — nullable JSON (localized admin response)
- `refund_processed_at` — nullable timestamp

## 2. Backend Changes

### Model: `app/Models/SupportInquiry.php`
- Add new fields to `$fillable` and `$casts`
- Add `booking()` BelongsTo relationship
- Add scope: `scopeType($query, $type)` for filtering by type

### Migration update
- Run the migration to alter the existing table

### Controller: `app/Http/Controllers/Api/ClientController.php`
- Modify `createSupport()` to accept `type`, `category`, `booking_id`, `refund_amount`, `refund_reason`
- Add validation: if type=refund_request, booking_id required, refund_amount required
- Verify booking belongs to the authenticated user
- Add `getClientComplaints()` method — returns user's complaints/refund requests

### Controller: New `app/Http/Controllers/Api/AdminSupportController.php`
- `index()` — list all support inquiries with filters (type, status, priority)
- `show($id)` — single inquiry detail with booking info
- `update($id)` — admin can update status, priority, assign_to, admin_response
- `approveRefund($id)` — approve refund request, set refund_status=approved
- `rejectRefund($id)` — reject refund request, set refund_status=rejected, record admin_response
- `processRefund($id)` — mark as refunded, set refund_processed_at

### Routes: `routes/api.php`
Add under the auth middleware group:
```
// Client complaint/refund endpoints
Route::get('/client/complaints', [ClientController::class, 'complaints']);
Route::post('/client/complaints', [ClientController::class, 'createComplaint']);

// Admin support management
Route::get('/admin/support', [AdminSupportController::class, 'index']);
Route::get('/admin/support/{id}', [AdminSupportController::class, 'show']);
Route::put('/admin/support/{id}', [AdminSupportController::class, 'update']);
Route::post('/admin/support/{id}/approve-refund', [AdminSupportController::class, 'approveRefund']);
Route::post('/admin/support/{id}/reject-refund', [AdminSupportController::class, 'rejectRefund']);
Route::post('/admin/support/{id}/process-refund', [AdminSupportController::class, 'processRefund']);
```

### Notifications
- Extend `SupportInquiryNotification` to include type info
- New `RefundStatusNotification` for notifying clients of refund approval/rejection
