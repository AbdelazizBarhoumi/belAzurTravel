# Fix: Visa form flag field "required" error after country auto-fill

## Root Cause

In `AdminVisas.tsx`, when a country is selected via `LocationSelect` (with `countryOnly`), the `onChange` handler passes the full English country name (e.g., `"France"`) to `countryCodeToFlag()`. But that function requires a 2-letter ISO code (e.g., `"FR"`) — since `"France".length !== 2`, it returns `""`, and the validation `if (!values.flag)` triggers the "required" error.

**Trace:**
1. `LocationSelect` line 132: `onChange(loc.nameEn)` → passes `"France"`
2. `AdminVisas.tsx` line 206: `setField('flag', countryCodeToFlag("France"))` → returns `""`
3. `AdminVisas.tsx` line 138: `if (!values.flag)` → `true` → error shown

## Fix

**File: `resources/js/pages/admin/AdminVisas.tsx`** — Change the `LocationSelect` `onChange` handler (lines 204-209) to use `loc.code` (the ISO code from `allLocations`) for `countryCodeToFlag`, and use `loc.nameEn` for the name fields.

The problem is that `LocationSelect` only exposes one value via `onChange`. We have two options:

### Option A (minimal, recommended): Look up the ISO code from the country name inside the handler

```tsx
onChange={(val) => {
    setField('code', val);
    // Look up the ISO code from the English name to generate the flag
    const allCountries = Country.getAllCountries();
    const match = allCountries.find(
        (c) => countries.getName(c.isoCode, 'en') === val || c.isoCode === val,
    );
    setField('flag', match ? countryCodeToFlag(match.isoCode) : countryCodeToFlag(val));
    setField('name_en', val);
    setField('name_fr', val);
    setField('name_ar', val);
}}
```

This requires importing `Country` from `country-state-city` and `countries` from `i18n-iso-countries` into `AdminVisas.tsx`.

### Option B (cleaner long-term): Change `LocationSelect` to pass the ISO code

Modify `LocationSelect` to pass `loc.code` (ISO) instead of `loc.nameEn` when `countryOnly` is true. This would fix the root cause but requires auditing all other `LocationSelect` callers to ensure they still work with an ISO code value.

### Recommendation: Option A

Option A is the minimal, safe fix — it doesn't change the `LocationSelect` contract, so no risk of breaking other forms. The ISO code lookup is cheap and happens once per selection.
