# Fix: Navbar subcategory search links update URL but don't trigger search

## Root Cause

When clicking a subcategory link from the navbar (e.g., `/hotels?q=turkay`) while already on the hotels page (`/hotels`), React Router performs client-side navigation. The `Hotels` component re-renders (because `useSearchParams()` triggers it), but the `searchQuery` state is initialized via `useState(initialSearch)` which only reads the initial value once. The URL changes but the component's local state stays stale.

The `key={params.toString()}` on the wrapper `<div>` is intended to force a full remount when params change, but it doesn't work because React's reconciliation doesn't guarantee a remount when a key changes on a div inside the same component — the parent component (`Hotels`) itself doesn't remount, so the function body re-executes but `useState` still holds its previous value.

**The same bug exists on all listing pages**: hotels, tours, destinations, travels, deals, events, cars, partners.

## Fix

Add `useEffect` hooks to sync local state with URL search params on every listing page. This is the standard React pattern for "URL-driven state" with `useSearchParams`.

### Files to modify (8 pages):

1. **`resources/js/pages/hotels/index.tsx`** — add useEffect to sync `searchQuery` and `categoryTypeFilters` with `params`
2. **`resources/js/pages/tours/index.tsx`** — same pattern
3. **`resources/js/pages/destinations/index.tsx`** — same pattern (also sync `selectedCategory`, `selectedCountry`)
4. **`resources/js/pages/travels/index.tsx`** — same pattern
5. **`resources/js/pages/deals/index.tsx`** — same pattern
6. **`resources/js/pages/events/index.tsx`** — same pattern
7. **`resources/js/pages/cars/index.tsx`** — same pattern
8. **`resources/js/pages/partners/index.tsx`** — same pattern

### Pattern for each page (hotels example):

```typescript
// After the existing useState calls, add:
useEffect(() => {
    setSearchQuery(params.get('q') || params.get('destination') || '');
}, [params]);

useEffect(() => {
    const filters: Record<string, string[]> = {};
    for (const [key, val] of params.entries()) {
        if (key.startsWith('category_')) {
            const typeKey = key.slice('category_'.length);
            filters[typeKey] = val.split(',').filter(Boolean);
        }
    }
    setCategoryTypeFilters(filters);
}, [params]);
```

The `key={params.toString()}` can be removed from each page since the `useEffect` approach is more reliable and doesn't cause a full unmount/remount flash.

## Verification

1. Navigate to `/hotels` (no query params) → all hotels shown
2. From navbar, click Hotels → subcategory (e.g., "turkey") → URL changes to `/hotels?q=turkey` AND the search input shows "turkey" AND hotel list is filtered
3. From navbar, click Hotels → "Categories" (main link) → URL changes to `/hotels?cat=` AND all hotels shown
4. Test the same flow on tours, destinations, travels, deals, events, cars, partners pages
