# Fix: Preserve form values on validation error in EntityFormDialog

## Problem

When a validation error occurs (client-side or server 422), the `EntityFormDialog` resets all form values back to the original `initial` data. Users lose all their edits — every field they filled in is wiped.

## Root Cause

**File:** `resources/js/components/forms/EntityFormDialog.tsx`

Two mechanisms cause the unwanted reset:

### 1. `key={formKey}` on the `<form>` element (line 453)

```tsx
<form key={formKey} onSubmit={handleSubmit} noValidate ...>
```

`formKey = initialSignature` (a JSON string of the initial values). When the parent re-renders (which happens when `setErrors()` is called), the `dialogInitial` object gets a new reference. If `initialSignature` changes even slightly, React **unmounts and remounts the entire form**, destroying all internal state including the `values` useState.

### 2. `useEffect` dependency on `initial` object reference (line 382-390)

```tsx
useEffect(() => {
    if (open) {
        setValues(toRecord(initial, preserveArrayKeys));
        setLocalErrors({});
    }
    // ...
}, [open, initialSignature, initial, preserveArrayKeys]);
```

The `initial` prop is a new object on every parent render (most admin pages don't memoize `dialogInitial`). Even though the JSON-serialized `initialSignature` stays the same, React's `Object.is` comparison on the `initial` object reference returns `false`, causing the effect to re-run and call `setValues(toRecord(initial))` — resetting the form.

### Trigger chain

1. User fills in form, clicks Save
2. Server returns 422 → parent's `onError` calls `setErrors(err.data.errors)`
3. Parent re-renders → `dialogInitial` gets new object reference
4. EntityFormDialog receives new `initial` prop → `useEffect` fires → `setValues(toRecord(initial))` → **all edits lost**

## Fix

**Single file change:** `resources/js/components/forms/EntityFormDialog.tsx`

### Change 1: Remove `key={formKey}` from the `<form>` element

```diff
- <form key={formKey} onSubmit={handleSubmit} noValidate className="...">
+ <form onSubmit={handleSubmit} noValidate className="...">
```

The `key` was intended to force a reset when switching entities, but the `useEffect` already handles that via `initialSignature`. The `key` is redundant and destructive — it causes a full unmount/remount cycle that also wipes state in child components (ImagePicker, JsonListEditor, etc.).

### Change 2: Remove `initial` from `useEffect` dependency array

```diff
- }, [open, initialSignature, initial, preserveArrayKeys]);
+ }, [open, initialSignature, preserveArrayKeys]);
```

`initialSignature` is a string derived from `JSON.stringify(toRecord(initial))`. It only changes when the actual entity data changes (e.g., editing a different hotel). Removing the `initial` object reference from deps means the effect won't re-run when the parent re-renders with the same data under a new object reference.

### Change 3: Remove `formKey` variable (now unused)

```diff
- const formKey = initialSignature;
```

Dead code after Change 1.

## What this preserves

- **Opening a new entity**: `initialSignature` changes → effect runs → values initialized correctly
- **Closing the dialog**: `open` becomes false → effect runs → values cleared
- **Validation error**: `errors` state changes → parent re-renders → but `initialSignature` stays same → values preserved
- **Language tab switching**: Handled by `activeLang` state inside the dialog, independent of this flow

## Files to modify

- `resources/js/components/forms/EntityFormDialog.tsx` (3 changes described above)

## Verification

1. Open an admin page (e.g., AdminHotels)
2. Click Edit on an entity, fill in several fields
3. Leave a required field empty, click Save → validation error shows, all other field values are preserved
4. Fix the error, click Save → success
5. Click Add, fill fields, click Save with validation error → values preserved
6. Close the dialog and reopen → form is fresh
7. Switch language tabs → form values persist across tab switches
8. Edit entity A, close, edit entity B → form shows B's values (not A's)
