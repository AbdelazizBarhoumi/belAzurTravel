# Plan: Replace Manual Country/City Text Inputs with Localized Dropdowns

## Overview
Replace country and city text inputs with localized dropdown selects. Selecting a country populates the city dropdown with cities from that country. Auto-fills localized fields (en/fr/ar). Address in Site Settings stays as free text.

## Current State — Files with Manual Location Inputs

| Page | Field | Type | Localized? |
|------|-------|------|-----------|
| `resources/js/pages/admin/AdminHotels.tsx` | `country`, `city` | text inputs | Yes (en/fr/ar) |
| `resources/js/pages/admin/AdminDestinations.tsx` | `country` | text input | Yes (en/fr/ar) |
| `resources/js/pages/admin/AdminSiteSettings.tsx` | `address` | text input | No (plain string) |

**Backend controllers:**
- `app/Http/Controllers/AdminHotelController.php` — `country_en/fr/ar`, `city_en/fr/ar`
- `app/Http/Controllers/AdminDestinationController.php` — `country_en/fr/ar`
- `app/Http/Controllers/SiteSettingsController.php` — `address` (string, **no change**)

## Implementation Steps

### Step 1: Install composer package
```bash
composer require wixela/prisma-country
```
Run migrations to get countries/states/cities tables.

### Step 2: Backend — API Endpoint
Create `app/Http/Controllers/Api/LocationController.php`:
- `GET /api/locations/countries` — all countries with en/fr/ar translations
- `GET /api/locations/countries/{code}/cities` — cities for a country

Response format:
```json
{
  "data": [
    { "code": "TN", "name": { "en": "Tunisia", "fr": "Tunisie", "ar": "تونس" } }
  ]
}
```

Register routes in `routes/api.php`.

### Step 3: Frontend — Shared Components
Create `resources/js/components/ui/CountrySelect.tsx`:
- Fetches countries from `/api/locations/countries` (React Query, cached)
- Dropdown showing localized country names based on active language
- Accepts current value + `onValueChange(code, names)` callback
- On select, auto-fills `{field}_en`, `{field}_fr`, `{field}_ar` via callback

Create `resources/js/components/ui/CitySelect.tsx`:
- Takes `countryCode` prop, fetches cities from `/api/locations/countries/{code}/cities`
- Disabled when no country selected
- Shows localized city names based on active language
- On select, auto-fills `{field}_en`, `{field}_fr`, `{field}_ar`

Create `resources/js/hooks/useCountries.ts` and `resources/js/hooks/useCities.ts` for data fetching.

### Step 4: Update AdminHotels.tsx
**Lines ~444-456:** Replace the text input fields for `city` and `country` with:
```tsx
<CountrySelect
  value={values.country_en} 
  lang={activeLang}
  onChange={(code, names) => {
    setField('country_en', names.en);
    setField('country_fr', names.fr);
    setField('country_ar', names.ar);
  }}
/>
<CitySelect
  countryCode={selectedCountryCode}
  value={values.city_en}
  lang={activeLang}
  onChange={(code, names) => {
    setField('city_en', names.en);
    setField('city_fr', names.fr);
    setField('city_ar', names.ar);
  }}
/>
```

### Step 5: Update AdminDestinations.tsx
**Line ~472:** Replace `country` text input with `CountrySelect` component.

### Step 6: AdminSiteSettings.tsx
**No changes** — address stays as free text input.

### Step 7: No Backend Changes
Existing localized field pattern (`country_en/fr/ar`, `city_en/fr/ar`) works as-is. The dropdowns just auto-fill these fields from the API data. No database migrations needed for existing data.
